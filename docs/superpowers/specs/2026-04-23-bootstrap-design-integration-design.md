## 一、目标与非目标

### 1.1 核心使命

让 Bootstrap 完成后的项目仓库具备 design 阶段所需的全部样板文件与配置字段；在 FINALIZE 后主动推送"绑定 Claude Design"提醒卡；在第一个 `needs_ui=true` REQ 进入时懒检查绑定状态，确保 design 阶段可正常运行。

### 1.2 非目标（本轮明确不做）

- **不自动化 DS 快照同步**：DS 从 Claude Design export zip → 同步到 `design/system/` 的自动化留到 v2。本轮 `design/system/` 只占位 `.gitkeep`
- **不做前端脚手架代码 scaffold**：实际前端代码（Vite + React + TS + Tailwind + shadcn/ui 初始化）需要单独设计规格；本轮只在 `src/{pkg}_webapp/` 创建 `.gitkeep` 占位
- **不改造 Claude Design 外部工具**：其无可控 API，只约定绑定 URL 字段
- **不迁移既有项目**：本层变更对 already-bootstrapped 项目无追溯；既有项目缺失内容由后续 REQ 走 `project_context_change` gate 补齐或手工 PR

### 1.3 适用范围

- 本层影响 Bootstrap Step 4（POPULATE_MAIN）和 Step 7（FINALIZE）
- 仅对 bootstrap_log 中 `POPULATE_MAIN` 之前未 ok 的 project 生效（`--resume` 语义）
- 已完成 Bootstrap 的项目不被触发

## 二、Bootstrap 流程（现有 7 步 + 新增 post-FINALIZE 动作）

```
现有 7 步（IntEnum 不变）：
  1. VALIDATE
  2. UPSERT_CONFIG
  3. CREATE_REPO
  4. POPULATE_MAIN ── ★ 新增 8 个 design 相关文件到 populate_files
                     ★ 新增 frontend_subpath / frontend_tech_stack 回写到 ProjectConfig
                     ★ architecture_templates YAML render 输出包含 UI Context 节
  5. CREATE_ARCHITECTURE_DOC
  6. CREATE_FEISHU_GROUP
  7. FINALIZE ─────── ★ 成功完成后推"Claude Design 绑定提醒卡"到创建群
                      失败不阻断 FINALIZE（best-effort）

【Bootstrap 结束】

Post-FINALIZE 异步：
  用户点绑定卡输入框 → 回填 claude_design_project_url
        │
        ▼
  /cards/bind-claude-design handler
    → ProjectConfig.claude_design_project_url 更新
    → 返回 success toast
  （幂等，可重复更新 URL）

独立时间线：
  第一个 needs_ui=true REQ 进入 CoordinatorService.design_start:
    if ProjectConfig.claude_design_project_url == "":
        raise ValueError("Claude Design 未绑定")
    service_app 层捕获 → 推阻断卡（复用绑定卡形态 + 错误提示）
    用户在阻断卡上填完 URL → 重走 approve 路径（已通过的 approve 不回退，
      仅需重新触发 design_start；可通过 /design restart <req> 或直接让
      final_review_passed 再 retry——MVP 走 /design restart）
```

## 三、分工

| 角色 | 干什么 | 不干什么 |
|---|---|---|
| **Bootstrap Service** (`project_bootstrap/service.py`) | Step 4 写 design 样板文件；Step 7 成功后推绑定卡；ProjectConfig 写入 frontend 字段 | 不做绑定确认；不校验 Claude Design URL 有效性 |
| **Static Content** (`project_bootstrap/static_content.py`) | 渲染 design/* 样板内容 + 扩展 CLAUDE.md + 新增 `.gitattributes` | 不做动态逻辑 |
| **Architecture Templates** (`docs/context/architecture-templates/*.yaml`) | 声明 frontend/design 字段 | 不渲染 Markdown 节（由 `render_template` 附加） |
| **ProjectConfig** (`project_config.py`) | 持久化 3 个新字段 | 不负责业务语义（空 URL 表示未绑定是约定） |
| **CoordinatorRuntimeApp** (`service_app.py`) | 接收绑定卡 action；lazy check 在 design_start 失败时推阻断卡 | 不做 Bootstrap 步骤编排 |
| **CoordinatorService** (`coordinator_service.py`) | `design_start` 首行加绑定 guard | 不发卡（guard 只 raise） |
| **人（项目 owner / 设计负责人）** | Bootstrap 完成后点卡绑定；必要时搭 Claude Design Project + Import repo | - |

### 4.4 `render_template()` 输出追加 UI Context 节

修改 `architecture_templates.py:render_template()`：在现有字符串替换后，若 YAML 解析出有 `frontend` 或 `design` 字段，追加一段 Markdown 节到输出末尾：

```python
def render_template(category, *, project, seed=None) -> tuple[str, str]:
    version, path = _latest_template_path(category)
    raw = path.read_text(encoding="utf-8")
    # ... 现有字符串替换 ...
    text = ...

    # 新增：解析 YAML，追加 UI Context 节
    parsed = yaml.safe_load(raw)
    ui_context_section = _build_ui_context_section(parsed)
    if ui_context_section:
        text += "\n\n" + ui_context_section

    return version, text


def _build_ui_context_section(parsed: dict) -> str | None:
    frontend = parsed.get("frontend")
    design = parsed.get("design")
    if not frontend and not design:
        return None

    lines = ["## UI Context", ""]
    if frontend:
        lines.append(f"- **前端栈**：{_fmt_tech_stack(frontend.get('tech_stack', {}))}")
        lines.append(f"- **前端代码位置**：`{frontend.get('subpath', '')}`")
    else:
        lines.append("- **前端**：本 category 默认无前端（若需管理后台见 enterprise-app）")
    if design:
        lines.append(
            f"- **设计工具**：Claude Design（project URL 见 `project_configs.yaml` "
            f"→ `design.claude_design_project_url`）"
        )
        lines.append(f"- **Design System 快照**：`{design.get('design_system_snapshot_path', '')}`")
        lines.append(f"- **Page Registry**：`{design.get('pages_registry_path', '')}`")
    return "\n".join(lines)


def _fmt_tech_stack(stack: dict) -> str:
    if not stack:
        return "（未定义）"
    return " / ".join(f"{k}: {v}" for k, v in stack.items())
```

def design_start(
    self,
    req_id: str,
    *,
    design_doc_id: str = "",
    design_doc_url: str = "",

    # ... 既有 apply_design_event + hook firing 逻辑 ...

`service_app.dispatch_design_start_if_needed` 捕获该 ValueError：

```python
def dispatch_design_start_if_needed(app, requirement) -> None:
    if not requirement.needs_ui:
        return
    # ... create_design_document ...
    try:
        app.service.design_start(requirement.req_id, ...)
    except ValueError as exc:
        msg = str(exc)
        if "Claude Design 未绑定" in msg:
            # 推阻断卡（复用绑定卡内容 + 错误说明）
            try:
                app._emit_design_binding_reminder_card_from_runtime(
                    requirement.project, error_context=msg,
                )
            except Exception:
                LOGGER.exception(
                    "emit binding card after guard fail failed req=%s",
                    requirement.req_id,
                )
            return
        LOGGER.warning("design_start failed req_id=%s: %s", requirement.req_id, exc)
```

### 7.2 失败回退

| 失败点 | 行为 |
|---|---|
| Step 4 POPULATE_MAIN 失败（任一新文件写不进去） | 与既有 populate 失败一样，整个 step 失败；`bootstrap_log` 记 error；`--resume` 从 CREATE_REPO 重跑 |
| `parse_template_yaml` / `_build_ui_context_section` 对某 category 失败 | 不阻塞 populate（最多 ARCHITECTURE.md 缺 UI Context 节）；记 warning |
| FINALIZE 后推送绑定卡失败 | 仅记 warning；FINALIZE 状态仍为 ok；用户后续可通过 `/design rebind <project>` CLI 重推（后续增量） |
| 绑定 card action handler 失败 | 返回 error toast；ProjectConfig 不变；用户可重试 |
| Lazy check 触发阻断 | `design_start` raise；service_app 捕获转推阻断卡；用户绑定后需重新走 approve flow（通过 `/design restart <req>` 或等下一次 approve） |
